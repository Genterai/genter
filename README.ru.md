**На картинке Genter Cloud** на вымышленной команде, как её показывает [страница-пример](https://genter.ai/try) без
входа: страница Notion нигде не говорит, что её заменили, и чтобы найти заменившую её ветку в Slack, нужна модель.
**Что для чего нужно:** без ключа открытый движок Genter отмечает то, что документ говорит о себе сам (заменён, устарел,
статус ADR), и ставит актуальный ответ первым. Противоречие, которое никто не записал, требует модели: Genter Cloud
находит его уже сейчас, открытый движок пока нет (в планах: с вашим ключом или Ollama).

## Ваш репозиторий, без ключа

**Тест старого ответа.** 39 вопросов, ответ на которые заменён более новым документом: 34 из публичных архивов решений
(PEP Python, KEP Kubernetes, RFC и ADR Jaeger) и 5 из [DriftBench](bench/drift). Обычное ранжирование, каким
пользуется агент, оставляет заменённый документ без отметки в первой пятёрке в 31 из 39; Genter в 0 из 39, и каждый
раз цитирует собственную пометку документа. Старый ответ первым Genter всё же ставит в 7 из 39 (обычное ранжирование: в
8 из 39): это PEP, чей `Superseded-By:` называет номер, а не файл, поэтому Genter отмечает их, но не может поднять
замену наверх. Каждый вопрос и каждый проигрыш: [bench/old-answer/RESULTS.md](bench/old-answer/RESULTS.md) (вопросы
по архивам ещё ждут проверки человеком).

| из 39 вопросов ([результаты](bench/old-answer/RESULTS.md)) | обычное ранжирование | Genter, без ключа |
| -- | --: | --: |
| старый ответ без отметки в первой пятёрке | 31 из 39 | **0 из 39** |
| старый ответ первым | 8 из 39 | 7 из 39 |
| актуальный ответ первым | 20 из 39 | 21 из 39 |

Genter читает то, что ваши документы говорят о себе сами ([readers/](readers)): ADR, RFC в папках `rfc/` и `rfcs/`,
PEP Python, KEP Kubernetes, версии и устаревшее в CHANGELOG, журнал `docs/decisions.md`, пометку «Superseded by»,
«Deprecated» или «Заменён» в начале документа, front matter Obsidian. Многие репозитории хранят свои записи там, куда
ридеры пока не заглядывают: в медианном из 50 популярных репозиториев 0 записей, которые читают ридеры
([bench/repos/RESULTS.md](bench/repos/RESULTS.md)), а ридер — это JSON-файл, который может добавить любой
([CONTRIBUTING.md](CONTRIBUTING.md)).

## Genter Cloud: приложения вашей команды

Почему что-то устроено именно так, редко написано в коде. Это в тикете, ветке в Slack или письме.
[Genter Cloud](https://genter.ai) подключает ваши приложения (GitHub, Linear, Slack, Gmail, Notion, Google Drive и
другие) и с помощью модели отмечает, что заменило или опровергло более новое сообщение, страница или тикет.
[Страница-пример](https://genter.ai/try) показывает его записанные ответы на Kestrel Works, вымышленной команде, без
входа.

Это отдельный MCP-сервер, `https://genter.ai/api/mcp`, рядом с локальным `genter mcp`. При первом подключении ваш
ИИ-инструмент проводит вход через OAuth; genter-cli никогда не обращается к Genter Cloud и ничего не хранит для него на
диске. У агента появляются одни и те же два инструмента от каждого, `search` и `read`: `genter` для ваших папок и
`genter-cloud` для приложений.

### Добавить Genter Cloud в Claude

В Claude (веб, десктоп или мобильное приложение): [Customize › Connectors](https://claude.ai/customize/connectors) ›
**Add custom connector**, вставьте `https://genter.ai/api/mcp` и нажмите **Add**; Claude проведёт вход в Genter. На
бесплатном тарифе Claude можно добавить один свой коннектор
([руководство Claude](https://claude.com/docs/connectors/custom/add-unlisted)). В Claude Code:

```bash
claude mcp add --transport http genter-cloud https://genter.ai/api/mcp
```

### Добавить Genter Cloud в ChatGPT

В ChatGPT: [Plugins](https://chatgpt.com/plugins) › **+** › **Add custom MCP server**, дайте имя, в разделе Connection
выберите публичный адрес и вставьте `https://genter.ai/api/mcp`, выберите OAuth, подтвердите и нажмите **Create as a
plugin** ([руководство OpenAI](https://developers.openai.com/apps-sdk/deploy/connect-chatgpt)). Можно ли добавить свой
сервер, решают правила вашего аккаунта или рабочего пространства.

Cursor, VS Code и другие клиенты, которые принимают удалённый MCP-сервер, добавляют тот же адрес;
`npx genter-cli install --cloud` добавляет его в такие инструменты на вашем компьютере.

## Локальный движок

**MCP-сервер, команда и библиотека, которые дают агенту место, где записан ответ.** Спрашивайте своими словами. Genter
возвращает отрывки, которые отвечают на вопрос, прочитанные только что, с файлом и строками, датой, которую документ
указывает сам, и отметками. Нет индекса, который надо строить и синхронизировать, поэтому нет и копии, которая устареет.
Нет зависимостей и сервера, а без ключа для эмбеддингов ничего не покидает ваш компьютер.

```bash
npx genter-cli demo                     # 1. решение заменено, ваш ИИ первым получает новое: офлайн, без ключа
npx genter-cli ask "how do we deploy?"  # 2. спросите папку, в которой вы находитесь (ранжирование по словам)
npx genter-cli install                  # 3. дайте его своим ИИ-инструментам (покажет каждое изменение и спросит)
```

У агента два инструмента, те же, что у Genter Cloud, оба только для чтения: `search {query, limit}` находит отрывки и
возвращает каждое место с id, `path:lines`, датой и отметками; `read {ids}` читает места целиком, какими они стали
сейчас. Как добавить его в Claude Code плагином, в другие MCP-клиенты и в репозиторий всей команды:
[Add it to your AI tools](README.md#add-it-to-your-ai-tools).

## Что он читает

- Каждый файл или страница — это **Anchor**: одно чтение с фиксированным аргументом. Genter хранит, где он лежит, его
  заголовки, даты и дайджест, но никогда не копию текста.
- Каждый вопрос читает источники заново. Изменённый файл отвечает новым текстом с отметкой «changed since the last
  look». Когда файл проекта сам помечает себя `Deprecated: replaced by [v2](v2.md)` и v2 тоже в проекте, v2 идёт первым,
  а файл сразу за ним, с цитатой собственной пометки; пометка откуда-то ещё видна на своём месте и ничего не двигает.
- Дата решения — та, что указывает сам документ (`Date:` в ADR, заголовок CHANGELOG, front matter). Если все файлы
  папки записаны в пределах секунд (свежий клон), Genter пишет «file dates unknown (fresh clone)» вместо времени
  клонирования.
- Ридеры в [`readers/`](readers) — это данные, они никогда не запускаются, и добавить свой может любой; фразы, которыми
  страница помечает себя заменённой, лежат в [`rules/`](rules), на английском и русском.
- Genter никогда не читает скрытые файлы, файлы из `.gitignore`, lock-файлы, ключи и всё, где есть приватный ключ.

## Страница решений

```bash
npx genter-cli decisions   # в клоне: ~/.genter/pages/<проект>.html
```

Одна страница решений проекта: каждый ADR, RFC и заголовок `docs/decisions.md`, актуальный или заменённый, с местом
(`path:line`) и датой, которую документ указывает сам. Заменённый цитирует собственную пометку и называет, что его
заменило. Каждая строка — то, что документ говорит о себе: без модели, без ключа, без дат файлов, и ни одна строка не
утверждает, что два документа расходятся (для этого нужна модель). Страница цитирует ваши документы, поэтому пишется
вне репозитория и доступна только вам: проверьте её, прежде чем делиться. Это один HTML-файл без скриптов, он
открывается офлайн и помечен коммитом, на котором сделан.

## Бенчмарки

Каждое число здесь получено запуском открытого кода из [`bench/`](bench), который может повторить любой, без ключа и
аккаунта. Собственные числа Genter Cloud здесь не приводятся.

- **[Тест старого ответа](bench/old-answer)**: таблица наверху; каждый вопрос, каждый проигрыш и правило решения из
  плана — в [RESULTS.md](bench/old-answer/RESULTS.md). Пересобирает `node bench/old-answer/run.mjs`.
- **[Проверка на 50 репозиториях](bench/repos)**: у медианного репозитория 0 записей решений, которые читают ридеры;
  28 из 50 содержат хотя бы один документ с пометкой, которую ридеры читают
  ([RESULTS.md](bench/repos/RESULTS.md)). Пересобирает `node bench/repos/run.mjs`.
- **[DriftBench](bench/drift)**, LoCoMo и LongMemEval: таблицы, которые пишет сам запуск, — в
  [английском README](README.md#benchmarks).
